# المخطط المعماري الشامل للميزات التحويلية لمنصة TaskFlow (الإصدار 3.1.0)
*صيغ واعتمد بالإجماع من قبل هيئة معماريي النظم، واجهات المستخدم، والأنظمة الموزعة*
*المهارات الحاكمة: doubt-driven-development, constraint-driven-development, security-and-hardening, ux-writing*
*سياسة خلو الرموز التعبيرية: مطبقة بصرامة تامة (أحرف ASCII قياسية، أيقونات SVG متجهية، ورموز Ant Design الرسمية فقط)*

## الملخص التنفيذي وإجماع هيئة الوكلاء

تنتقل منصة TaskFlow من مجرد لوحة مهام تقليدية تؤدي عمليات الإدخال والتعديل البسيطة (CRUD)، إلى بيئة عمل هندسية فائقة الإنتاجية تضاهي منصات عالمية رائدة مثل Linear وRaycast وStripe. من خلال تطبيق منهجية "التطوير المبني على الشك" (Doubt-Driven Development) واختبارات الضغط التقاطعية بين الوكيل الأول (معمار تجربة وواجهة المستخدم)، والوكيل الثاني (معمار الواجهة الخلفية والأنظمة الموزعة)، والوكيل الثالث (قائد النظم الاستراتيجية والقدرات الفائقة)، صاغت الهيئة واعتمدت **5 ميزات نوعية وتحويلية**.

تستند كافة الميزات إلى ثلاثة ثوابت معمارية غير قابلة للتفاوض:
1. **تزامن حتمي وتكامل علائقي سليم:** معاملات فائقة السرعة على محرك SQLite في أجزاء من الميلي ثانية، وتحكم تفاؤلي في التزامن (OCC)، ونماذج أخطاء معيارية متوافقة مع RFC 9457.
2. **تصميم وظيفي رفيع عالي الكثافة:** واجهات نظيفة خالية من الزخارف المصطنعة والرموز التعبيرية، تعتمد على خطوط ذات أرقام متساوية العرض (tabular-nums)، مع تكافؤ كامل بين اللغتين الإنجليزية (LTR) والعربية (RTL).
3. **بنية مرنة لمقاومة حالات الفشل:** معالجة سلسة لحالات انقطاع الاتصال، وتراجع ذري عن التعديلات الجماعية، ونسخ احتياطي حي دون إيقاف المحرك، وقوائم أحداث ذات سعة محددة.

```
+---------------------------------------------------------------------------------------------------+
|                                  الهيكلية المعمارية الشاملة لـ TASKFLOW                            |
+---------------------------------------------------------------------------------------------------+
|                                                                                                   |
|  [ طبقة الواجهة الأمامية: Next.js 16.4 / React 19 / AntD / Tailwind ]                             |
|  - محرك الإدخال السريع (مفتاح C)         - رصيف الإجراءات الجماعي العائم (تحديد متعدد)             |

|          | استدعاءات REST (تعديلات OCC)                ^ تدفق أحداث SSE (/api/projects/:id/events)|

|                                                                                                   |

|                                                                                                   |
|          | عمليات كتابة ذرية متزامنة                   | فحص خلفي تعاوني                           |

+---------------------------------------------------------------------------------------------------+
```

## 1. الميزة الأولى: محرك الإدخال السريع باللغة الطبيعية (Omni-Capture Task Engine)

### 1.1 تعريف المشكلة
تستهلك عملية إنشاء المهام عبر النوافذ التقليدية ما بين 12 إلى 18 ثانية لكل مهمة، مما يقطع تركيز المهندس وتدفقه الذهني بسبب تكرار النقر، والتنقل بين الحقول، واختيار التواريخ من القوائم المنسدلة.

### 1.2 مواصفات تجربة وواجهة المستخدم (UX/UI)
- **طريقة التفعيل:** 
  - الضغط على المفتاح السريع `C` من أي مكان داخل لوحة المشروع لفتح شريط الإدخال العائم أعلى الشاشة.
  - صف إدخال مثبت ومستمر بعنوان `[+ مهمة سريعة]` / `[+ Quick Task]` في أعلى عمود المهام قيد الانتظار (Todo).
- **قواعد بناء الجمل باللغة الطبيعية:**
  - النص القياسي: `[نص عنوان المهمة] @assignee !priority #tag due:YYYY-MM-DD`
  - تكافؤ لغوي كامل مع اللغة العربية: معالجة طبيعية لأسماء الأيام والتواريخ النسبية (`اليوم`, `غدا`, `غداً`, `بعد غد`, `الاثنين`, `الثلاثاء`)، وشارات الأولوية (`!عاجل`, `!مرتفع`, `!متوسط`), وحسابات الأعضاء (`@محمد`).
  - معالجة النصوص العربية: توحيد الألف والياء وإزالة التشكيل لضمان دقة التعرف البرمجي.
- **التفكيك التفاعلي والهروب من الرموز (Escaping):**
  - تحويل فوري للرموز المستخرجة إلى شرائح بصرية عالية التباين (Chips).
  - الهروب من الرموز: إذا كان عنوان المهمة يحتوي بطبيعته على رمز خاص، يمكن تجاوزه باستخدام الشرطة المائلة (`\@`, `\!`, `\#`) أو حصر العبارة بين علامتي اقتباس `"..."` (مثال: `"حل مشكلة الـ @mentions في المحلل"`).
  - إذابة الشرائح: الضغط على زر `Backspace` عند حافة الشريحة يعيدها فورا إلى نصها الأصلي القابل للتعديل دون ضياع أي حرف.
- **حماية حقول الإدخال النشطة (Keyboard Trap Defense):**
  - تعطيل المفتاح `C` تماما إذا كان المؤشر داخل أي حقل إدخال نصي (`INPUT` أو `TEXTAREA` أو `contentEditable`).
- **التوافق التام مع الهواتف الذكية:**
  - زر دائم أعلى عمود المهام يفتح لوحا سفليا متجاوبا يركز المؤشر تلقائيا على حقل الإدخال.

### 1.3 التصميم البرمجي في الواجهة الخلفية ونماذج التزامن
- **نقطة النهاية:** `POST /api/projects/:id/tasks`
- **التنفيذ في المتصفح:** محلل نحوي خفيف في الذاكرة (<2ms) يحول النص إلى كائن برمجي مطابق لمخطط Zod.
- **الحفظ الذري:**
  - تنفيذ الحفظ عبر دالة `withTransaction(BEGIN IMMEDIATE)`.
  - إدراج المهمة مع ضبط الإصدار الأولي `version = 1`.
  - تسجيل قيد النشاط `TASK_CREATED` في جدول التدقيق.
  - إدراج حدث `task.created` في جدول المهام المؤجلة `outbox`.
- **ضمان سرعة الاستجابة:** إدراج تفاؤلي في واجهة المستخدم خلال أقل من 16 ميلي ثانية، واكتمال الحفظ في الخادم في أقل من 80 ميلي ثانية.

## 2. الميزة الثانية: رصيف الفرز والتعديل الجماعي والإلغاء الذري (Multi-Card Bulk Triage & Action Dock)

### 2.1 تعريف المشكلة
تنظيم وتعديل المهام أثناء التخطيط السريع يتطلب نقل وتعديل وحذف كل بطاقة على حدة، مما يجبر المستخدم على تنفيذ عشرات العمليات اليدوية المكررة.

### 2.2 مواصفات تجربة وواجهة المستخدم (UX/UI)
- **آلية التحديد:**
  - أجهزة سطح المكتب: النقر الفردي للاختيار، والنقر مع `Cmd`/`Ctrl` للاختيار المتعدد، والنقر مع `Shift` لتحديد نطاق متصل من البطاقات داخل العمود، والمفتاح `X` لتحديد البطاقة الحالية.
  - الشاشات التي تعمل باللمس: زر `[تحديد / Select]` في شريط الأدوات يظهر مربعات اختيار واضحة على جميع البطاقات.
- **رصيف الإجراءات العائم عالي التباين:**
  - يظهر بسلاسة في منتصف أسفل الشاشة بمجرد تحديد بطاقتين أو أكثر (`selectedCards.length >= 2`).
  - المظهر الهندسي: سطح مصمت عالي التباين (`#1B243B` للنمط الليلي / `#FFFFFF` للنمط النهاري) مع إطار دقيق بسمك 1 بكسل وخال تماما من مؤثرات الزجاج الشفاف غير العملية.
  - الإجراءات المتاحة:
    - تغيير الحالة الجماعي: المفاتيح السريعة (`1` لقيد الانتظار، `2` لقيد التنفيذ، `3` للمكتملة).
    - تعيين الأولوية الجماعي: المفتاح `P` متبوعا بالحرف الأول (`H` عالي، `M` متوسط، `L` منخفض).
    - التعيين الجماعي للأعضاء: المفتاح `A`.
    - تعديل تاريخ الاستحقاق الجماعي: المفتاح `D`.
    - الحذف الجماعي الآمن: المفتاح `Backspace` مع نافذة تأكيد قطعية.
- **حماية عمليات السحب والإفلات أثناء التحديد:**
  - في حال سحب أي بطاقة أثناء وجود تحديد جماعي، تنفذ عملية النقل حصريا على البطاقة المسحوبة، مع الإبقاء التام على التحديد الجماعي دون تشويه.
- **إشعار التراجع الموحد لمدة 6 ثوان:**
  - إشعار فوري: `تم نقل 12 مهمة إلى قيد التنفيذ. [تراجع (6 ثوانٍ)]` / `12 tasks moved to In Progress. [Undo (6s)]`.

### 2.3 التصميم البرمجي في الواجهة الخلفية ونماذج التزامن
- **نقطة النهاية:** `PATCH /api/projects/:id/tasks/bulk`
- **هيكل البيانات المرسل:**
  ```json
  {
    "taskIds": ["task-101", "task-102", "task-103"],
    "updates": {
      "status": "in_progress",
      "priority": "high"
    },
    "expectedVersions": {
      "task-101": 2,
      "task-102": 5,
      "task-103": 1
    }
  }
  ```
- **ضمان الشمولية أو الإلغاء الكامل (All-or-Nothing):**
  - التحقق المسبق من الصلاحيات في الذاكرة تحت قفل القراءة.
  - فتح معاملة فورية حصرية `BEGIN IMMEDIATE`.
  - مقارنة مصفوفة `expectedVersions` بالإصدارات الحالية في قاعدة البيانات؛ في حال وجود اختلاف في أي مهمة، تلغى المعاملة كاملة ويرجع الخادم خطأ 409 Conflict مع قائمة المهام المتعارضة `{ conflictingTaskIds: [...] }`.
  - تحديث كافة المهام المسندة وزيادة أرقام الإصدارات، وتسجيل قيود `TASK_BULK_UPDATED` في جدول الأنشطة.
  - إرسال حدث SSE موحد `tasks_bulk_updated` لكافة المتصلين.
- **نقطة نهاية التراجع الذري:** `POST /api/projects/:id/tasks/bulk-revert` لاسترجاع الحالة السابقة بدقة متناهية.

## 3. الميزة الثالثة: فاحص المهام المنقسم جانبيا والتنقل عبر الصف الرئيسي (Split-Pane Inspector & Traversal)

### 3.1 تعريف المشكلة
تؤدي النوافذ المنبثقة الكاملة والأدراج المنزلقة العريضة إلى حجب باقي أعمدة لوحة الكانبان وقطع سياق المتابعة أثناء مراجعة المهام في الاجتماعات السريعة.

### 3.2 مواصفات تجربة وواجهة المستخدم (UX/UI)
- **محرك التنقل عبر مفاتيح الصف الرئيسي:**
  - `J` / السهم لأسفل: الانتقال إلى البطاقة التالية في العمود الحالي.
  - `K` / السهم لأعلى: الانتقال إلى البطاقة السابقة في العمود الحالي.
  - `H` / السهم لليسار و `L` / السهم لليمين: الانتقال أفقيا بين أعمدة الكانبان.
  - **قاعدة الانعكاس البصري للغة العربية:** عند تفعيل الاتجاه من اليمين لليسار (`dir="rtl"`), ينعكس دور المفتاحين `H` و `L` تلقائيا ليتطابق التنقل مع الاتجاه البصري للأعمدة.
  - `Space` / `Enter`: فتح أو إغلاق الفاحص الجانبي المدمج للمهمة المحددة.
  - `Escape`: إغلاق الفاحص وإعادة حلقة التركيز عالية التباين إلى البطاقة النشطة.
- **التكيف الهندسي حسب أبعاد الشاشة:**
  - الشاشات الكبيرة (1600 بكسل فما فوق): تقسيم مدمج دائم بنسبة 70% للوحة الكانبان و30% للفاحص الجانبي دون أي تداخل أو إخفاء للأعمدة.
  - الشاشات المتوسطة (1024 إلى 1599 بكسل): لوح جانبي مرن مع دفع لوحة الكانبان أفقيا بسلاسة.
  - الشاشات الصغيرة (أقل من 1024 بكسل): لوح سفلي كامل يدعم السحب للإغلاق.
- **مكونات الفاحص الجانبي:**
  - تعديل فوري لعنوان المهمة ووصفها النصي الغني عبر محرر Markdown.
  - شريط متابعة المهام الفرعية بأرقام ثابتة العرض (`font-variant-numeric: tabular-nums`).
  - سجل زمني تاريخي للأنشطة يعرض صاحب كل تعديل، وتفاصيل التغيير، وتوقيته الدقيق.
  - شريط حل تعارض التعديل اللحظي (RFC 9457 Collision Banner): يظهر في حال قيام مستخدم آخر بتعديل البطاقة بالتزامن، مع زري مقارنة: `[الاحتفاظ بنسخة الخادم]` مقابل `[استبدال بتعديلي]`.

### 3.3 التصميم البرمجي في الواجهة الخلفية ونماذج التزامن
- **نقطة النهاية:** `GET /api/projects/:id/tasks/:taskId/audit` لإرجاع سجل الأنشطة والبيانات الفاصلة بدقة.
- **التحكم التفاؤلي في التزامن (OCC):**
  - ترسل طلبات التعديل ترويسة `If-Match: "version-<N>"` أو حقلا ضمن البيانات `{ version: <N> }`.
  - ينفذ الخادم الاستعلام التالي:
    `UPDATE tasks SET title = ?, ..., version = version + 1 WHERE id = ? AND version = ?;`
  - إذا كانت الصفوف المتأثرة صفرا، يرجع الخادم فورا استجابة `application/problem+json` برمز الحالة HTTP 409 Conflict.

## 4. الميزة الرابعة: محرك التزامن اللحظي عبر SSE ومنارات الحضور العابرة (Real-Time SSE Sync & Presence)

### 4.1 تعريف المشكلة
بدون نظام تزامن لحظي بين المستخدمين، يعمل أعضاء الفريق على بيانات قديمة وغير محدثة، مما يؤدي إلى الكتابة فوق تعديلات الآخرين وازدواجية تعيين المهام دون علمهم.

### 4.2 التصميم المعماري لنظام التزامن
- **وسيلة النقل المعتمدة: Server-Sent Events (SSE):**
  - المسار: `GET /api/projects/:id/events`
  - اختيار تدفق HTTP أحادي الاتجاه بدلا من WebSockets لضمان: انعدام العبء البرمجي الزائد، والتوافق الطبيعي مع بروتوكول HTTP/2، واستخدام ترويسات مصادقة JWT القياسية، وإعادة الاتصال التلقائي من المتصفح عبر `Last-Event-ID`.
- **نبضات منع انقطاع الاتصال وحماية الذاكرة:**
  - إرسال تعليق نبض دوري `: ping\n\n` كل 15 ثانية لمنع انقطاع الاتصال عند استخدام خوادم وسيطة مثل NGINX وCloudflare.
  - عند انقطاع الاتصال (`req.on('close')`), يتم فورا إلغاء تسجيل المستمع وحذف حضور المستخدم من الذاكرة لمنع تسرب موارد الخادم.
- **ذاكرة دائرية لآخر 100 حدث (Ring Buffer):**
  - يحتفظ كل مشروع نشط بذاكرة دائرية تتسع لـ 100 حدث في الذاكرة.
  - إذا عاد العميل بعد انقطاع مؤقت وبحوزته `Last-Event-ID: <seq>` ضمن نطاق الذاكرة، يبث الخادم فقط الأحداث الفائتة.
  - إذا كان المعرف قديما جدا وتجاوز سعة الذاكرة، يرسل الخادم حدث `event: sync_required` ليوجه المتصفح لإعادة جلب البيانات بهدوء في الخلفية.
- **منارة الحضور العابرة (Ephemeral Presence Beacon):**
  - المسار: `POST /api/projects/:id/presence` مع إرسال `{ taskId, action: "viewing" | "editing" }`.
  - جلسة حضور صالحة لمدة 30 ثانية تنتهي تلقائيا عند إغلاق التبويب أو فقدان نبضتين متتاليتين.
  - المظهر البصري: شارات صغيرة تضم الأحرف الأولى للمستخدمين النشطين تظهر أعلى البطاقات وفي ترويسة الفاحص لمنع تضارب العمل.

## 5. الميزة الخامسة: قيود سعة الأعمدة وسجل التدقيق المشفر ومجدول التنبيهات (WIP Limits & SLA Dispatcher)

### 5.1 قيود سعة العمل الحركية (WIP Limits) وشريط مؤشرات صحة السبرنت
- **حوكمة سعة الأعمدة:**
  - قيود مرنة قابلة للتخصيص لكل عمود تحفظ في إعدادات المشروع (مثال: `wip_limits: { in_progress: 5, review: 3 }`).
  - الحالات البصرية:
    - الحالة الطبيعية: عداد أرقام ثابتة العرض (`3 / 5`).
    - حالة تجاوز الحد: تحول الترويسة إلى تباين تحذيري مع شارة تنبيه (`6 / 5 - تم تجاوز السعة`).
    - التنبيه المرن افتراضيا: يمكن للمستخدم إفلات المهمة مع ظهور رسالة تنبيه غير معطلة، مع إمكانية تفعيل المنع الصارم اختياريا من إعدادات المشروع (`strict_wip_enforcement: true`).
- **شريط مؤشرات صحة السبرنت (Sprint Telemetry Ribbon):**
  - شريط علوي عالي الكثافة يعرض 4 مقاييس دقيقة خالية من الرسوم الزائفة:
    1. إجمالي المهام النشطة (Scope) بأرقام ثابتة العرض.
    2. نسبة إشغال السعة الحالية (Active WIP Ratio).
    3. نسبة المهام المتأخرة عن مواعيدها (Overdue Rate).
    4. متوسط دورة الإنجاز (Lead / Cycle Time) بالساعات من لحظة الإنشاء حتى الإكمال.

### 5.2 سجل تدقيق الأنشطة المشفر بسلسلة SHA-256 وإمكانية استرجاع الحالات
- **مخطط الجدول: `task_activities`**
  ```sql
  CREATE TABLE IF NOT EXISTS task_activities (
    id TEXT PRIMARY KEY,
    task_id TEXT NOT NULL,
    project_id TEXT NOT NULL,
    actor_id TEXT NOT NULL,
    action TEXT NOT NULL,
    diff_payload JSON NOT NULL,
    snapshot JSON,
    sequence_number INTEGER NOT NULL,
    prev_hash TEXT,
    current_hash TEXT NOT NULL,
    created_at TEXT NOT NULL,
    FOREIGN KEY (task_id) REFERENCES tasks(id) ON DELETE CASCADE,
    FOREIGN KEY (project_id) REFERENCES projects(id) ON DELETE CASCADE,
    FOREIGN KEY (actor_id) REFERENCES users(id) ON DELETE CASCADE
  );
  ```
- **ترشيد استهلاك المساحة التخزينية:**
  - تخزين الفروقات فقط (Lean Diffs) للتعديلات الاعتيادية (`{ "field": "status", "from": "todo", "to": "in_progress" }`).
  - تخزين لقطة كاملة (Full Snapshot) فقط عند إنشاء المهمة وعند وصولها إلى حالة الاكتمال النهائية.
- **حماية البيانات من التلاعب:**
  - حساب الهاش المشفر: `current_hash = SHA256(prev_hash + sequence_number + task_id + action + diff_payload)`.
- **استرجاع النسخ السابقة (Time-Travel Reversion):**
  - المسار: `POST /api/projects/:id/tasks/:taskId/revert/:activityId`
  - تنفيذ عملية كتابة متقدمة ذرية تسترجع اللقطة السابقة مع رفع رقم الإصدار وإضافة قيد تدقيق جديد.

### 5.3 نمط المهام المؤجلة (Transactional Outbox) ومعالج التنبيهات الخلفي
- **مخطط الجدول: `outbox`**
  ```sql
  CREATE TABLE IF NOT EXISTS outbox (
    id TEXT PRIMARY KEY,
    event_type TEXT NOT NULL,
    payload JSON NOT NULL,
    scheduled_for TEXT NOT NULL,
    status TEXT NOT NULL DEFAULT 'pending',
    retry_count INTEGER NOT NULL DEFAULT 0,
    max_retries INTEGER NOT NULL DEFAULT 5,
    last_error TEXT,
    processed_at TEXT,
    created_at TEXT NOT NULL
  );
  ```
- **العامل التعاوني داخل الخادم:**
  - مهيأ عبر إعداد المحرك `PRAGMA wal_autocheckpoint = 1000;`.
  - يعمل بمؤقت تعاوني كل 10 ثوانٍ بخاصية `unref()`.
  - يعالج دفعات محددة بـ 25 حدثا في المرة الواحدة لمنع التزاحم على وحدة المعالجة.
  - يحسب تلقائيا تنبيهات اقتراب المواعيد النهائية، وعلامات التأخير، وأحداث الإخلال بمستويات الخدمة (SLA) دون التأثير على استجابة طلبات المستخدمين.

### 5.4 النسخ الاحتياطي الحي وسيادة البيانات
- **النسخ الاحتياطي الساخن أثناء التشغيل:**
  - المسار: `POST /api/admin/backup`
  - ينفذ أمر SQLite الحصري `VACUUM INTO ?;` لإنشاء نسخة نظيفة ومطابقة تماما لقاعدة البيانات على القرص دون إيقاف عمليات القراءة أو الكتابة الجارية.
- **تصدير تدفقي للبيانات (Streaming Exporter):**
  - المسار: `GET /api/projects/:id/export?format=json|csv`
  - تصدير تدفقي فوري يعالج آلاف المهام دون استهلاك زائد لذاكرة الخادم.
